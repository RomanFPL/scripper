# Scripper

Один репозиторій, дві частини:

- **`extension/`** — саме браузерне розширення (Manifest V3): статично
  прописаний набір дозволених дій (`ACTIONS`) + UI для вибору селектора,
  збору даних і керування завантаженнями.
- **`scenarios/`** — набір JSON-сценаріїв, які розширення підвантажує з
  віддаленого репозиторію через `fetch()`. Тут **немає жодного коду** —
  лише дані.

Розширення ніколи не завантажує і не виконує віддалений JavaScript.
Воно лише читає JSON-опис кроків і зіставляє кожен крок із заздалегідь
написаною функцією у `content.js`.

**Важливо:** попри назву "Video Runner" на ранніх етапах розробки, ядро
цього інструменту — узагальнений **рушій сценаріїв** (`ACTIONS` + JSON),
а не щось специфічне для відео. Наразі основний набір дій стосується
збору посилань і завантаження HLS-відео, але архітектура розрахована на
розширення новими діями — наприклад, парсингом довільних даних зі
сторінок, які переглядає користувач. Технічні деталі про повідомлення,
сховище та як додавати нові дії — у [`ARCHITECTURE.md`](ARCHITECTURE.md).

## Гарантії безпеки

- В коді немає `eval()`.
- В коді немає `new Function()`.
- Віддалені ресурси (`index.json`, `*.json` сценаріїв) запитуються лише
  через `fetch()` і парсяться як `response.json()` — жодного
  `<script src="...">`, `importScripts()` чи вставки коду в DOM.
- Усе, що може виконатись у сторінці користувача, — це фіксований набір
  функцій у `extension/content.js`, який постачається разом із
  розширенням і не змінюється під час роботи.
- Сценарій — це чисті дані (`{ action: "...", ... }`). Рушій лише зіставляє
  `step.action` з ключем у `ACTIONS` за іменем — довільний рядок ніколи не
  перетворюється на код.

## Структура репозиторію

```
extension/
├── manifest.json    — маніфест Manifest V3
├── background.js    — service worker: оркестрація сесій/завантажень,
│                       chrome.downloads, chrome.power
├── content.js        — ACTIONS registry, виконання сценарію, picker
│                       елементів, завантаження HLS на сторінці
├── offscreen.js       — збірка Blob (там, де є DOM, чого нема в SW)
├── offscreen.html
├── popup.html         — UI popup'а
└── popup.js           — вся логіка popup'а: сценарії, селектори, сесії,
                          пайплайн
scenarios/
├── index.json         — список доступних сценаріїв (name + file)
├── collect-video-links.json
└── download-hls-test.json
README.md
ARCHITECTURE.md
```

Ключове розділення: **код розширення** (`extension/`) незмінний і
завантажується локально через "Load unpacked". **Дані** (`scenarios/`)
живуть окремо й підтягуються з мережі — саме вони можуть змінюватись без
переустановлення розширення.

## Встановлення (Chrome)

1. Відкрити `chrome://extensions`.
2. Увімкнути перемикач **Developer mode** (Режим розробника) у правому
   верхньому куті.
3. Натиснути **Load unpacked** (Завантажити розпаковане розширення).
4. Вибрати папку `extension/` (саме `extension/`, не корінь репозиторію).
5. Розширення з'явиться в списку та в панелі інструментів.

## Встановлення (Brave)

1. Відкрити `brave://extensions`.
2. Увімкнути **Developer mode** (той самий перемикач, що й у Chrome —
   Brave використовує рушій Chromium і повністю сумісний з Manifest V3).
3. Натиснути **Load unpacked**.
4. Вибрати папку `extension/`.

## Як змінити SCENARIOS_INDEX_URL

Відкрити `extension/popup.js` і змінити константу на початку файлу:

```js
const SCENARIOS_INDEX_URL =
  "https://raw.githubusercontent.com/<user>/<repo>/main/scenarios/index.json";
```

Підійде будь-який публічний "raw" JSON-файл, наприклад:

- GitHub: `https://raw.githubusercontent.com/<user>/<repo>/<branch>/scenarios/index.json`
- GitLab: `https://gitlab.com/<user>/<repo>/-/raw/<branch>/scenarios/index.json`

Шляхи `file` у самому `index.json` — **відносні** до розташування
`index.json` (розширення саме резолвить їх через `new URL(file, indexUrl)`),
тому при перенесенні репозиторію на іншого власника чи гілку достатньо
змінити лише `SCENARIOS_INDEX_URL` — файли сценаріїв редагувати не треба.

Після зміни — перезавантажити розширення на сторінці `chrome://extensions`
(або `brave://extensions`) кнопкою "оновити" (⟳).

## Як користуватись

1. **Refresh list** — підвантажує `scenarios/index.json`, заповнює дропдаун
   **Scenario**.
2. Обрати сценарій (наприклад, той, що містить крок `collectLinks`) і
   натиснути **Load scenario**.
3. **Selector**: натиснути **+ Add**, вказати два CSS-селектори (item /
   link) вручну або через **Pick on page** (клік по елементу на сторінці
   підставляє селектор автоматично — дивись тост на самій сторінці, бо
   popup при цьому закривається, це нормальна поведінка Chrome). **Test**
   перевіряє селектор на поточній сторінці й показує кількість знайдених
   елементів; **Save** зберігає пару в історію. Збережені селектори — це
   список з олівцем (редагувати) і хрестиком (видалити) навпроти кожного.
4. **Collect links** — виконує обраний сценарій (з підставленими
   селекторами) на активній вкладці й відкриває нову **сесію-вкладку** в
   popup (одна сторінка = одна сесія; можна тримати кілька одночасно).
5. У сесії — чекбокс-список знайдених елементів (Select all/none),
   **Parallel downloads** (скільки одночасно), **Download selected** —
   запускає пайплайн у `background.js`, який продовжує працювати навіть
   якщо popup закрити. **Pause/Resume** і **Stop** керують ним;
   прогрес — окремий бар навпроти кожного елемента (зеленіє й знімає
   чекбокс по завершенню).

## Формат scenarios/index.json

```json
{
  "scenarios": [
    { "name": "Назва сценарію", "file": "collect-video-links.json" },
    { "name": "Інший сценарій", "file": "subdir/other.json" }
  ]
}
```

Правила:

- `index` — обов'язково JSON-об'єкт.
- `index.scenarios` — обов'язково масив.
- кожен елемент — обов'язково об'єкт із рядковими полями `name` і `file`.
- `file` — шлях відносно `index.json` (або повний `http(s)://` URL, якщо
  сценарій лежить в іншому місці).

## Формат scenario-файлу

```json
{
  "name": "Назва сценарію",
  "steps": [
    { "action": "log", "message": "Hello" },
    { "action": "getPageTitle", "saveAs": "title" },
    { "action": "wait", "ms": 1000 }
  ]
}
```

Правила:

- `scenario` — обов'язково JSON-об'єкт.
- `scenario.steps` — обов'язково масив.
- кожен `step` — обов'язково об'єкт із рядковим полем `action`.
- `step.saveAs` (опційно) — ім'я змінної, під яким результат кроку
  збережеться в локальному об'єкті `variables` під час виконання сценарію.
- решта полів (`message`, `ms`, `selector`, ...) — параметри конкретної дії.

Селектори для `collectLinks` зазвичай **не** зашиваються в JSON намертво —
popup підставляє їх динамічно з UI-полів `Selector` (див. "Як
користуватись" вище), тому той самий сценарій-файл підходить для будь-якого
сайту.

## Доступні actions

| action         | параметри                              | опис                                                                 |
|----------------|------------------------------------------|-----------------------------------------------------------------------|
| `log`          | `message`                               | виводить `message` у консоль сторінки (`console.log`)                 |
| `wait`         | `ms`                                     | чекає `ms` мілісекунд                                                  |
| `getPageTitle` | —                                        | повертає `document.title`                                             |
| `query`        | `selector`                               | повертає елемент через `document.querySelector`; помилка, якщо не знайдено |
| `click`        | `selector`                               | знаходить елемент за `selector` і викликає `.click()`                  |
| `getText`      | `selector`                               | знаходить елемент за `selector` і повертає `.innerText`                |
| `collectLinks` | `selector`, `linkSelector`               | знаходить усі елементи за `selector`, у кожному шукає посилання за `linkSelector` (як предок через `closest`, так і нащадок через `querySelector`), повертає масив `{index, title, url}` |
| `downloadHLS`  | `url?`, `title?`, `videoUrl?`, `pipelineSessionId?`, `filename?` | шукає HLS-плейлист (auto-detect через `performance`, якщо `url` не задано), якщо треба — обирає варіант з найвищим бітрейтом з master playlist, якщо є `#EXT-X-MAP` — тягне init+сегменти fMP4, інакше — сегменти MPEG-TS; зберігає файл через `chrome.downloads` |

Кожен крок, у якого є `saveAs`, зберігає свій результат у
`variables[saveAs]` всередині поточного запуску сценарію.

Повний перелік внутрішніх повідомлень і схему сховища для цих двох дій —
дивись `ARCHITECTURE.md`.

## Обробка помилок

Усі помилки — явні, без "тихих" збоїв. Формат:

```
❌ Scenario failed at step 3:
Action "click" failed:
Element not found: #video
```

Якщо `step.action` не відповідає жодній зареєстрованій дії, кидається
помилка `Unknown action: "..."` із номером кроку.

## Як додати новий сценарій

1. Покласти новий `*.json`-файл у папку `scenarios/` (формат — див. вище).
2. Додати запис `{ "name": "...", "file": "новий-файл.json" }` у
   `scenarios/index.json`.
3. Запушити зміни у репозиторій (без переустановлення розширення!).
4. У popup натиснути **Refresh list** — новий сценарій одразу з'явиться в
   дропдауні.

## Як додати нову статичну action

1. Відкрити `extension/content.js`.
2. Додати нову функцію в об'єкт `ACTIONS`, наприклад:

   ```js
   const ACTIONS = {
     // ...existing actions...
     myNewAction(step, variables) {
       // тільки статичний, наперед написаний код.
       // step — параметри з JSON-сценарію (дані, не код).
       return someResult;
     },
   };
   ```

3. Якщо дія може падати (елемент не знайдено, невірний параметр тощо) —
   кидати `throw new Error("зрозумілий опис")`. Runner сам обгорне цю
   помилку в повідомлення `Scenario failed at step N: ...`.
4. Перезавантажити розширення в `chrome://extensions` / `brave://extensions`.
5. Тепер нову дію можна викликати з будь-якого сценарію в `scenarios/`,
   вказавши `"action": "myNewAction"`.

Дія завжди має бути написана й включена в код розширення заздалегідь.
Віддалений JSON ніколи не додає нову логіку — він лише обирає, у якому
порядку й з якими параметрами викликати вже наявні статичні дії.

Якщо нова дія має власний окремий етап (не одноразовий `RUN_SCENARIO`, а
щось довготривале на кшталт `downloadHLS`, з прогресом, чергою, паузою) —
дивись розділ "Сесії та пайплайн" в `ARCHITECTURE.md`, де описано, як
`collectLinks`/`downloadHLS` вже інтегровані в цю модель, і як за тим самим
патерном підключити щось нове (наприклад, парсинг/збір довільних даних).

## Поточний стан і напрямок розвитку

Вже реалізовано: збір посилань за довільним CSS-селектором (з picker'ом і
історією збережених селекторів), завантаження HLS (fMP4 і MPEG-TS),
сесії-вкладки на кілька сторінок одночасно, паралельні завантаження з
паузою/зупинкою, прогрес-бари по кожному елементу, `chrome.power`
(не давати Mac заснути під час пакетного завантаження).

Заплановано (поза межами відео): додавання нових `ACTIONS` для парсингу й
збору довільних даних зі сторінок — за тим самим статичним патерном, без
жодних змін архітектури безпеки.

## Vanilla JS, без збірки

Проєкт не використовує React, TypeScript, Webpack, Vite, npm, бандлери чи
зовнішні бібліотеки. Це звичайний vanilla JavaScript, який одразу
завантажується через "Load unpacked" (з папки `extension/`) — без кроку
збірки.
